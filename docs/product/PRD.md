- 정상 상황, 실패 상황과 경계 상황에서 제품이 어떻게 동작하는지
- AI가 무엇을 알고 어떤 행동까지 할 수 있는지
- 기능이 완료됐다고 판단할 수 있는 수용 기준
- 출시 전 반드시 통과해야 하는 품질 기준

## 1. 제품 요약

### 1.1 제품 정의

밥벌이는 사용자가 선택한 유튜브 요리 영상의 링크를 입력하면 재료와 조리 단계를 구조화하고, 실제 요리 중에는 현재 진행 상황을 기억하며 질문에 답하는 Android용 AI 요리 동행 앱이다.

### 1.2 해결하려는 핵심 문제

유튜브 요리 영상은 메뉴를 발견하고 조리 모습을 이해하는 데 유용하지만, 실제 조리 도구로 사용할 때 다음 문제가 발생한다.

1. 재료와 분량이 영상 여러 구간에 흩어져 있다.
2. 필요한 장면을 찾기 위해 영상을 반복해서 되감아야 한다.
3. 조리 중 손이 젖거나 더러워져 화면을 조작하기 어렵다.
4. 불 세기, 익힘 상태, 농도와 재료 대체처럼 영상에 없는 판단이 필요하다.
5. 범용 AI는 사용자가 보고 있는 레시피와 현재 단계를 매번 다시 설명해야 한다.

### 1.3 제품 가치 제안

> 유튜브 요리 영상을 실행 가능한 레시피로 바꾸고, 사용자의 현재 조리 상황을 기억하며 요리가 끝날 때까지 대화로 돕는다.

### 1.4 핵심 제품 원칙

1. **원본 우선**: AI가 원본 영상의 권위를 대체하지 않는다. 사용자는 언제든 근거 영상 구간을 확인할 수 있다.
2. **현재 상황 우선**: 일반적인 요리 지식보다 현재 레시피, 현재 단계와 사용자 변경사항을 먼저 반영한다.
3. **불확실성 공개**: 영상에서 확인되지 않은 분량, 시간과 방법을 사실처럼 단정하지 않는다.
4. **짧고 실행 가능하게**: 조리 중 답변은 읽기 쉬운 길이와 즉시 수행 가능한 행동으로 제공한다.
5. **안전 우선**: 익힘, 알레르기, 화상과 식품 안전 질문에서는 편의보다 보수적인 판단을 우선한다.
6. **사용자 통제**: AI가 레시피나 조리 상태를 임의로 확정하지 않는다. 중요한 변경은 사용자가 확인한다.

## 2. 목표와 비목표

### 2.1 MVP 목표

MVP는 다음 제품 가설을 검증한다.

> 사용자가 선택한 유튜브 요리 영상을 구조화된 레시피로 확인하고, 현재 단계를 기억하는 AI와 대화하면 영상 되감기와 별도 검색이 줄어들고 실제 요리 완료 및 반복 사용이 증가한다.

구체적인 목표는 다음과 같다.

- 유튜브 링크 입력부터 조리 시작까지 하나의 끊기지 않는 흐름을 제공한다.
- 사용자가 추출 결과를 검토하고 잘못된 정보를 수정할 수 있게 한다.
- 조리 중 현재 단계와 사용자 변경사항을 유지한다.
- 짧은 텍스트 또는 음성 발화로 다음 행동과 문제 해결 방법을 얻을 수 있게 한다.
- 각 조리 단계에서 원본 영상의 관련 구간으로 이동할 수 있게 한다.
- 사용자가 하나의 요리를 완료하고 다른 영상에서도 다시 사용할 이유를 검증한다.

### 2.2 MVP 비목표

다음 기능은 MVP에서 제공하지 않는다.

- 냉장고 재료 관리
- 보유 재료 기반 메뉴 추천
- 레시피 탐색 피드와 인기 레시피 랭킹
- 장보기 목록과 가격 비교
- 영수증 저장과 OCR
- 캘린더 연동
- 식단 및 영양 관리
- 커뮤니티, 댓글과 팔로우
- 크리에이터용 콘텐츠 관리 도구
- 영상 파일 원본 저장 또는 재배포
- 항상 듣고 있는 음성 비서
- 카메라로 조리 상태를 자동 판별하는 기능
- 전문 의료·영양 상담
- 업장용 대량 조리 지원

## 3. 대상 사용자

### 3.1 1차 타겟

유튜브 요리 영상을 실제로 따라 만들지만 조리 경험이 충분하지 않아 영상을 반복 탐색하고 중간 판단에서 자주 막히는 20~30대 1~2인 가구 사용자.

### 3.2 행동 기준

나이보다 다음 행동을 타겟 판별의 우선 기준으로 사용한다.

- 유튜브 또는 쇼츠에서 요리 영상을 저장한다.
- 월 2회 이상 영상을 따라 실제 요리를 시도한다.
- 재료와 분량을 찾기 위해 영상을 되감은 경험이 있다.
- 조리 중 별도 검색 또는 메신저 질문을 한 경험이 있다.
- 재료 대체, 불 세기 또는 익힘 상태 판단에 자신이 없다.

### 3.3 대표 페르소나

#### 페르소나 A  퇴근 후 요리하는 자취 직장인

- 평일 저녁 20~40분 안에 한 끼를 만들고 싶다.
- 출퇴근 중 저장한 유튜브 쇼츠나 영상을 따라 한다.
- 계량과 불 조절에 자신이 없다.
- 손을 씻고 영상을 되감는 행동을 번거롭게 느낀다.
- 긴 설명보다 지금 할 행동 하나를 원한다.

#### 페르소나 B  새로운 메뉴에 도전하는 초보 사용자

- 익숙한 요리는 만들 수 있지만 새로운 요리는 영상에 의존한다.
- 영상과 자신의 결과가 다를 때 원인을 판단하기 어렵다.
- 원본 영상을 신뢰하지만 필요한 장면을 빨리 찾고 싶다.
- 실패했을 때 버리기보다 복구 방법을 묻고 싶다.

### 3.4 핵심 JTBD

> 내가 고른 요리 영상을 실제로 따라 만들 때, 필요한 정보를 다시 찾거나 현재 상황을 매번 설명하지 않고도 다음 행동과 문제 해결 방법을 알고 싶다. 그래야 요리를 중단하지 않고 원하는 결과에 가깝게 완성할 수 있다.

### 3.5 초기 비대상 사용자

- 전문 조리사와 레시피 개발자
- 식당용 대량 조리 사용자
- 정밀한 의료 식단이 필요한 사용자
- 오븐 온도와 계량 오차에 매우 민감한 전문 베이킹 사용자
- 레시피 추천과 식단 계획이 주목적인 사용자

## 4. 사용자 시나리오

### 4.1 핵심 시나리오

1. 사용자는 유튜브에서 만들고 싶은 요리 영상을 발견한다.
2. 공유 버튼에서 밥벌이를 선택하거나 앱에 링크를 붙여넣는다.
3. 앱은 링크와 영상 지원 가능 여부를 확인한다.
4. 앱은 분석 진행 상태와 예상 대기 상황을 표시한다.
5. AI가 레시피 초안을 생성한다.
6. 사용자는 재료, 분량과 단계를 검토하고 필요한 부분을 수정한다.
7. 사용자는 요리 시작을 누른다.
8. 앱은 첫 단계와 해당 단계에서 필요한 재료를 표시하고 읽어준다.
9. 사용자는 “여기까지 했어”라고 말한다.
10. 앱은 현재 단계를 완료 처리하고 다음 단계를 안내한다.
11. 사용자는 “물이 너무 많아”라고 질문한다.
12. AI는 현재 레시피와 단계에 맞는 복구 행동을 짧게 제시한다.
13. 사용자는 “영상으로 보여줘”라고 요청한다.
14. 앱은 현재 단계의 근거 타임스탬프로 원본 영상을 연다.
15. 사용자는 앱으로 돌아와 다음 단계를 계속한다.
16. 마지막 단계가 끝나면 사용자는 요리 완료를 선택한다.
17. 앱은 세션을 완료 처리하고 짧은 만족도 질문을 제시한다.

### 4.2 보조 시나리오

#### 링크가 지원되지 않는 경우

1. 앱은 분석을 시작하기 전에 지원 불가 이유를 설명한다.
2. 사용자가 확인할 수 있는 대안을 제시한다.
3. 실패한 분석은 사용량으로 차감하지 않는다.

#### 자막이 없는 경우

1. 앱은 현재 방식으로 분석 가능한 정보가 부족함을 표시한다.
2. 영상 설명 등으로 제한된 분석이 가능하면 정확도가 낮을 수 있음을 알린다.
3. 사용자가 제한적 분석을 계속할지 취소할지 선택하게 한다.

#### 앱이 종료된 경우

1. 진행 중 조리 세션을 로컬에 즉시 저장한다.
2. 앱 재실행 시 진행 중인 요리가 있음을 표시한다.
3. 사용자가 이어하기 또는 종료를 선택한다.

## 5. 정보 구조와 화면 목록

### 5.1 MVP 내비게이션

MVP는 복잡한 하단 탭 구조를 사용하지 않는다. 홈, 레시피 결과, 조리 세션이라는 단순한 계층을 사용한다.

```text
앱 시작
└─ 홈
   ├─ 링크 입력
   ├─ 분석 중
   ├─ 분석 실패
   ├─ 레시피 검토
   │  ├─ 재료 수정
   │  └─ 단계 수정
   ├─ 요리 준비
   └─ 조리 세션
      ├─ 현재 단계
      ├─ AI 대화
      ├─ 원본 영상 구간
      ├─ 일시정지
      └─ 완료
```

| S-02 | 홈 | 링크 입력 또는 공유 링크 확인 | 분석 시작 |
| S-03 | 분석 중 | 처리 상태와 취소 방법 제공 | 분석 취소 |
| S-04 | 분석 실패 | 원인 이해와 재시도 | 다시 시도 |
| S-05 | 레시피 검토 | AI 추출 결과 확인 | 수정, 요리 준비 |
| S-06 | 항목 수정 | 잘못된 재료 또는 단계 수정 | 저장 |
| S-07 | 요리 준비 | 전체 재료와 조리 개요 확인 | 요리 시작 |
| S-08 | 조리 모드 | 현재 단계 수행 | 완료, 질문, 영상 확인 |
| S-09 | AI 대화 | 현재 문맥 기반 질문 | 텍스트 또는 음성 전송 |
| S-10 | 영상 구간 | 원작자의 실제 동작 확인 | 앱으로 돌아가기 |
| S-11 | 일시정지 확인 | 세션 상태 보존 | 이어하기, 종료 |
| S-12 | 요리 완료 | 완료 기록과 만족도 수집 | 종료 |
| S-13 | 저장한 레시피 | 이전 분석 결과 재사용 | 열기, 다시 요리 |
| S-14 | 설정 | 음성, 개인정보와 계정 관리 | 설정 변경 |

## 6. 조리 세션 상태 모델

### 6.1 상태 정의

| 상태 | 설명 | 진입 조건 | 종료 조건 |
|---|---|---|---|
| `DRAFT` | 추출 레시피 검토 전 | 분석 성공 | 사용자가 검토 시작 |
| `REVIEWING` | 사용자가 추출 내용을 확인 중 | 레시피 화면 진입 | 준비 완료 또는 이탈 |
| `READY` | 요리 시작 가능 | 필수 검토 완료 | 요리 시작 |
| `COOKING` | 현재 조리 진행 중 | 사용자가 요리 시작 | 일시정지, 완료, 중단 |
| `PAUSED` | 진행 상태를 보존한 일시정지 | 사용자 일시정지 또는 앱 장기 백그라운드 | 이어하기 또는 중단 |
| `COMPLETED` | 사용자가 완료를 확인 | 마지막 단계 완료 또는 완료 버튼 | 종료 상태 |
| `ABANDONED` | 사용자가 명시적으로 중단 | 중단 확인 | 종료 상태 |

### 6.2 상태 전이 규칙

```text
DRAFT → REVIEWING → READY → COOKING → COMPLETED
                         ↘ PAUSED ↗
                         ↘ ABANDONED
```

- AI 답변만으로 단계를 자동 완료하지 않는다.
- “여기까지 했어”, “다 했어”, “다음”처럼 완료 의도가 명확한 발화는 현재 단계를 완료 처리할 수 있다.
- “다음이 뭐야?”는 정보 요청일 수 있으므로 현재 단계를 자동 완료하지 않는다.
- 마지막 단계에서 “다 했어”가 입력되면 완료 확인을 한 번 거친다.
- 사용자가 이전 단계로 이동하더라도 이미 완료한 단계 기록은 유지한다. 사용자가 명시적으로 되돌릴 때만 완료를 취소한다.
- 앱이 백그라운드로 이동해도 즉시 `PAUSED`로 바꾸지 않는다. 일정 시간 이상 복귀하지 않았을 때 UI에서 이어하기를 제안한다.

### 6.3 현재 단계 규칙

- 한 시점에 하나의 현재 단계만 존재한다.
- 단계 번호는 사용자 편집 이후 다시 연속적으로 정렬한다.
- 사용자가 단계 순서를 수정하면 진행 중 세션에는 즉시 적용하지 않고 확인을 받는다.
- 현재 단계에 연결된 재료, 도구, 시간과 원본 타임스탬프를 함께 저장한다.
- 사용자가 “두 단계 전으로 가줘”라고 요청하면 이동 전후 단계를 음성 또는 화면으로 확인시킨다.

## 7. 기능 요구사항

### 7.1 링크 입력과 공유

#### FR-URL-001 유튜브 URL 직접 입력

- 사용자는 홈 화면에 유튜브 URL을 붙여넣을 수 있어야 한다.
- 앞뒤 공백과 일반적인 공유 파라미터는 정규화한다.
- 동일한 영상의 여러 URL 형태를 하나의 영상 ID로 식별한다.
- URL이 비어 있거나 유튜브 URL이 아니면 분석 요청을 보내지 않는다.

**수용 기준**

- 정상적인 일반 영상 URL과 단축 URL을 인식한다.
- 지원하지 않는 URL은 1초 이내에 클라이언트 오류를 표시한다.
- 오류 메시지는 “잘못된 링크”로 끝내지 않고 지원 형식을 예시로 보여준다.

#### FR-URL-002 Android 공유 메뉴

- 유튜브 앱 또는 브라우저의 공유 메뉴에서 밥벌이를 선택할 수 있어야 한다.
- 앱이 종료된 상태에서도 공유된 URL을 수신해야 한다.
- 공유 텍스트에 URL 외 문장이 포함되면 첫 번째 지원 URL 후보를 추출한다.
- 공유된 URL을 즉시 분석하지 않고 확인 화면을 먼저 보여준다.

**수용 기준**

- 공유 진입 후 사용자가 어떤 영상이 선택됐는지 제목과 썸네일로 확인할 수 있다.
- 중복 탭 또는 연속 공유로 분석 요청이 두 번 생성되지 않는다.

#### FR-URL-003 영상 사전 검증

- 앱은 분석 전에 영상 존재 여부, 공개 접근 가능 여부와 지원 가능한 정보 존재 여부를 확인해야 한다.
- 비공개, 삭제, 연령 제한, 지역 제한 또는 실시간 영상 등 지원하지 않는 상태를 구분한다.
- 지원 불가 사유를 사용자 언어로 설명한다.

### 7.2 분석 작업

#### FR-ANL-001 분석 생성

- 분석 작업은 클라이언트가 아닌 서버 측 Edge Function을 통해 생성한다.
- 하나의 사용자와 영상에 진행 중인 분석이 있다면 중복 작업을 만들지 않는다.
- 동일한 영상의 검증된 기존 분석 결과가 있으면 재사용할 수 있다.
- 사용자별 수정본과 공용 추출 원본을 분리한다.

#### FR-ANL-002 분석 진행 상태

상태는 최소한 다음과 같이 구분한다.

- `QUEUED`
- `FETCHING_SOURCE`
- `EXTRACTING`
- `VALIDATING`
- `COMPLETED`
- `NEEDS_REVIEW`
- `FAILED`
- `CANCELLED`

- 사용자에게 내부 기술 용어를 그대로 노출하지 않는다.
- 일정 시간이 지나도 완료되지 않으면 앱을 닫아도 계속 처리된다는 안내를 제공한다.
- 취소가 가능한 시점과 불가능한 시점을 구분한다.

#### FR-ANL-003 추출 결과

추출 결과에는 다음 필드를 지원한다.

```yaml
title: string
source_video_id: string
source_title: string
source_channel: string
servings:
  value: number | null
  confidence: confirmed | inferred | unknown
total_time:
  minutes: number | null
  confidence: confirmed | inferred | unknown
ingredients:
  - name: string
    quantity: number | null
    unit: string | null
    preparation: string | null
    optional: boolean
    confidence: confirmed | inferred | unknown
    evidence: transcript excerpt or timestamp reference
tools:
  - name: string
steps:
  - order: integer
    instruction: string
    duration_seconds: integer | null
    heat_level: string | null
    ingredients_used: ingredient references
    cautions: string[]
    start_timestamp_seconds: integer | null
    end_timestamp_seconds: integer | null
    confidence: confirmed | inferred | unknown
```

#### FR-ANL-004 불확실성 표시

- `inferred` 또는 `unknown` 값은 화면에서 구분해야 한다.
- “영상에서 분량을 확인하지 못했어요”처럼 이유를 설명한다.
- 알 수 없는 값을 AI가 임의의 정확한 숫자로 채우지 않는다.
- 사용자가 불확실한 항목을 수정하면 사용자 확인값으로 저장한다.

#### FR-ANL-005 분석 실패

- 실패는 최소한 다음 범주로 분류한다.
  - 잘못된 URL
  - 접근할 수 없는 영상
  - 요리 영상으로 판단하기 어려움
  - 분석할 정보 부족
  - 외부 서비스 오류
  - AI 응답 형식 오류
  - 시간 초과
  - 사용자 취소
- 시스템 오류는 사용자의 무료 또는 유료 사용량에서 차감하지 않는다.
- 재시도는 멱등성을 유지해야 한다.

### 7.3 레시피 검토와 수정

#### FR-REV-001 검토 필수 항목

사용자는 요리 시작 전에 최소한 다음을 확인할 수 있어야 한다.

- 요리명
- 인분
- 전체 재료와 분량
- 조리 도구
- 전체 단계
- 불확실한 항목
- 원본 영상 정보

#### FR-REV-002 사용자 수정

- 사용자는 재료명, 분량, 단위, 선택 여부와 준비 방법을 수정할 수 있다.
- 사용자는 단계를 추가, 수정, 삭제하고 순서를 바꿀 수 있다.
- 원본 AI 결과는 감사 및 복구를 위해 별도로 보존한다.
- 수정 후 원본으로 되돌리기를 제공한다.
- 필수 단계가 모두 삭제되거나 내용이 비어 있으면 요리 시작을 허용하지 않는다.

#### FR-REV-003 중복 재료 정리

- 같은 재료가 다른 표현으로 반복되면 병합 후보를 제시할 수 있다.
- 자동 병합으로 원본 정보를 삭제하지 않는다.
- 예: `대파`, `다진 대파`, `대파 흰 부분`은 반드시 같은 재료로 단정하지 않는다.

### 7.4 조리 준비

#### FR-READY-001 준비 화면

- 전체 재료를 체크리스트로 제공한다.
- 필수 도구를 표시한다.
- 총 단계 수와 예상 시간을 표시하되 불확실한 값은 구분한다.
- 사용자가 준비 완료 여부와 관계없이 요리를 시작할 수는 있지만 미확인 재료가 있음을 알려준다.

#### FR-READY-002 음성 기능 안내

- 첫 조리 시작 전에 마이크 사용 목적을 설명한다.
- OS 권한 요청은 사용자가 음성 기능을 실제 선택하는 순간에만 수행한다.
- 마이크 권한을 거부해도 텍스트 모드로 모든 핵심 기능을 사용할 수 있어야 한다.

### 7.5 조리 모드

#### FR-COOK-001 현재 단계 화면

현재 단계 화면은 최소한 다음 순서로 정보를 제공한다.

1. 현재 단계 번호와 전체 단계 수
2. 지금 해야 할 행동
3. 이 단계에서 사용할 재료와 분량
4. 불 세기 또는 예상 시간
5. 주의사항
6. 원본 영상 구간 버튼
7. 완료, 이전, 질문 버튼

- 조리 모드에서는 화면 자동 꺼짐을 방지한다.
- 글자 크기 확대에도 핵심 버튼이 화면 밖으로 사라지지 않아야 한다.
- 한 화면에 모든 레시피를 넣지 않고 현재 단계의 인지 부담을 최소화한다.

#### FR-COOK-002 단계 완료

- 사용자는 버튼, 텍스트 발화 또는 음성 발화로 현재 단계를 완료할 수 있다.
- 완료 처리 후 다음 단계로 이동한다.
- 시간 기반 단계라도 타이머 종료만으로 자동 완료하지 않는다.
- 완료된 단계에는 완료 시각을 저장한다.

#### FR-COOK-003 단계 이동

- 이전 및 다음 단계로 자유롭게 이동할 수 있다.
- 완료되지 않은 현재 단계를 두고 다음 단계로 이동하려 하면 완료 여부를 묻거나 건너뛰기로 기록한다.
- 사용자가 탐색 목적으로 다음 내용을 확인한 것과 실제 진행 상태 변경을 구분한다.

#### FR-COOK-004 현재 단계 재료

- 전체 재료가 아니라 현재 단계에서 사용하는 재료와 분량을 우선 표시한다.
- 사용자 변경사항이 있으면 변경된 값을 표시한다.
- 원본과 다른 값에는 수정됨 표시를 제공한다.

#### FR-COOK-005 조리 세션 자동 저장

- 단계 이동, 사용자 변경사항, 대화에서 확정된 상태 변경은 즉시 저장한다.
- 네트워크가 끊기면 로컬에 기록하고 연결 복구 후 동기화한다.
- 충돌 시 가장 최근 변경을 무조건 덮어쓰지 않고 세션 단위 규칙을 적용한다.

### 7.6 원본 영상 타임스탬프

#### FR-TIME-001 단계별 타임스탬프

- 근거가 있는 단계에는 영상 시작 시점을 연결한다.
- 가능하면 종료 시점도 저장한다.
- 타임스탬프가 없는 단계에는 영상 버튼을 비활성화하거나 전체 영상 열기로 대체한다.

#### FR-TIME-002 영상 열기

- 사용자가 “영상으로 보여줘” 또는 영상 버튼을 선택하면 현재 단계의 타임스탬프에서 원본 영상을 연다.
- 원본 콘텐츠의 출처, 제목과 채널을 명확히 표시한다.
- 앱은 원본 영상을 자체 콘텐츠처럼 표시하거나 원본 파일을 저장하지 않는다.
- 영상에서 앱으로 돌아오면 조리 세션의 현재 단계를 유지한다.

#### FR-TIME-003 영상 재생 실패

- 유튜브 앱 미설치, 네트워크 오류 또는 영상 상태 변경 시 브라우저 열기 등 가능한 대안을 제공한다.
- 영상 재생 실패가 조리 세션을 종료시키지 않는다.

### 7.7 조리 대화

#### FR-CHAT-001 텍스트 입력

- 조리 중 언제든 텍스트 질문을 보낼 수 있다.
- 키보드가 열려도 현재 단계 핵심 정보와 전송 버튼을 확인할 수 있어야 한다.
- 전송 후 사용자가 질문한 시점의 단계 ID를 저장한다.

#### FR-CHAT-002 누르고 말하기

- 사용자가 마이크 버튼을 누른 동안 또는 명시적으로 녹음을 시작한 동안만 음성을 수집한다.
- 녹음 중임을 시각적으로 명확히 표시한다.
- 인식된 문장을 전송 전에 확인 또는 즉시 전송하도록 설정할 수 있다.
- 인식 실패 시 다시 말하기와 텍스트 입력을 제공한다.

#### FR-CHAT-003 답변 음성 낭독

- 조리 중 답변을 음성으로 읽어줄 수 있다.
- 사용자는 음성 낭독을 즉시 중지할 수 있다.
- 기본 답변은 20초 이내에 들을 수 있는 길이를 목표로 한다.
- 긴 설명이 필요한 경우 핵심 행동을 먼저 읽고 세부 내용은 화면에 제공한다.

#### FR-CHAT-004 의도 분류

최소한 다음 의도를 구분한다.

| 의도 | 예시 | 상태 변경 |
|---|---|---|
| `NEXT_STEP_INFO` | 다음은 뭐야 | 없음 |
| `COMPLETE_CURRENT_STEP` | 여기까지 했어 | 현재 단계 완료 |
| `GO_TO_NEXT_STEP` | 다음 단계로 넘어가 | 현재 단계 처리 후 이동 |
| `GO_TO_PREVIOUS_STEP` | 이전 단계 다시 보여줘 | 현재 단계 이동 |
| `REPEAT_INSTRUCTION` | 다시 말해줘 | 없음 |
| `SHOW_SOURCE` | 이 부분 영상으로 보여줘 | 없음 |
| `SUBSTITUTE_INGREDIENT` | 양파 대신 대파 써도 돼 | 확인 후 변경 가능 |
| `UPDATE_INGREDIENT` | 양파 대신 대파 넣었어 | 사용자 변경사항 저장 |
| `TROUBLESHOOT` | 너무 묽어 | 없음 |
| `TECHNIQUE_EXPLAIN` | 중불이 어느 정도야 | 없음 |
| `SAFETY_QUESTION` | 닭이 이 정도면 익은 거야 | 없음 |
| `SMALL_TALK` | 오늘 너무 피곤하다 | 없음 |
| `STOP_SESSION` | 요리 그만할래 | 확인 후 중단 |
| `UNKNOWN` | 해석하기 어려운 발화 | 명확화 질문 |

#### FR-CHAT-005 상태 변경 확인

- AI가 상태 변경 의도를 높은 확률로 판단할 때만 도구 호출을 제안한다.
- 재료 변경, 단계 삭제와 세션 종료처럼 결과에 영향을 주는 행동은 명시적 발화 또는 사용자 확인이 필요하다.
- 정보 질문은 기본적으로 상태를 변경하지 않는다.
- AI 응답 생성과 데이터 변경을 분리한다.

#### FR-CHAT-006 스몰토크

- AI는 조리 중 부담을 줄이는 짧은 스몰토크에 응답할 수 있다.
- 스몰토크 이후에도 현재 단계와 사용자 변경사항을 유지한다.
- 스몰토크가 길어지면 현재 요리가 진행 중임을 자연스럽게 상기시킬 수 있다.
- 감정 상담, 의료 상담, 연애 상담 등 범용 상담 기능으로 확장하지 않는다.
- 사용자가 명시적으로 원하지 않으면 요리와 무관한 대화를 먼저 시작하지 않는다.

#### FR-CHAT-007 답변 형식

조리 중 답변은 다음 우선순위를 따른다.

1. 지금 해야 할 행동
2. 필요한 시간, 불 세기 또는 확인 기준
3. 위험 또는 실패 방지 주의사항
4. 필요한 경우 원본 영상 확인 제안

예시:

```text
불을 중약불로 낮추고 1~2분 더 저어주세요.
주걱으로 바닥을 그었을 때 자국이 1초 정도 유지되면 다음 단계로 넘어가면 돼요.
계속 묽으면 영상의 04:12 구간과 현재 농도를 비교해 보세요.
```

#### FR-CHAT-008 답변 실패

- 답변 생성이 실패해도 사용자의 질문을 잃지 않는다.
- 재시도와 텍스트 안내를 제공한다.
- AI가 확신할 수 없는 경우 추측으로 상태를 변경하지 않는다.
- 위험도가 높은 질문에 확실한 판단이 불가능하면 중단과 확인을 권고한다.

### 7.8 저장과 재사용

#### FR-SAVE-001 레시피 저장

- 분석이 완료된 레시피는 자동 임시 저장한다.
- 사용자가 검토 또는 조리를 시작하면 사용자 레시피로 저장한다.
- 원본 분석 결과와 사용자 수정본을 구분한다.

#### FR-SAVE-002 동일 영상 재사용

- 같은 영상이 이미 분석됐다면 검증된 공용 결과를 재사용할 수 있다.
- 다른 사용자의 개인 수정사항은 노출하지 않는다.
- 공용 결과가 변경돼도 기존 사용자의 확정 레시피를 임의로 덮어쓰지 않는다.

#### FR-SAVE-003 삭제

- 사용자는 저장한 레시피와 조리 세션을 삭제할 수 있다.
- 계정 삭제 시 개인 데이터 삭제 범위와 처리 시간을 안내한다.
- 공용 분석 원본과 개인 데이터를 분리해 삭제 정책을 적용한다.

## 8. AI 동작 명세

### 8.1 AI 역할 분리

MVP에서는 하나의 범용 프롬프트로 모든 작업을 수행하지 않는다.

| 역할 | 책임 | 데이터 변경 권한 |
|---|---|---:|
| Recipe Extractor | 영상 정보를 구조화된 레시피로 변환 | 없음 |
| Extraction Validator | 필드 누락, 모순과 근거 연결 검사 | 없음 |
| Conversation Router | 사용자 발화 의도 분류 | 없음 |
| Cooking Companion | 현재 조리 문맥에 맞는 답변 생성 | 없음 |
| State Action Layer | 허용된 상태 변경 실행 | 제한적, 규칙 기반 |

### 8.2 대화 컨텍스트

Cooking Companion에는 필요한 정보만 전달한다.

- 확정된 레시피
- 현재 단계
- 직전 단계와 다음 단계
- 완료 또는 건너뛴 단계
- 사용자 변경사항
- 활성 타이머가 있다면 해당 정보
- 최근 대화 일부
- 이전 대화에서 추출한 결정 요약
- 안전 관련 사용자 정보가 명시적으로 제공된 경우 해당 정보

전체 대화 기록과 전체 자막을 매 요청마다 보내지 않는다.

### 8.3 근거 사용 규칙

- 레시피 고유 정보는 추출 레시피와 근거 구간을 우선한다.
- 일반적인 조리 지식으로 보완할 때는 원본 영상의 지시와 구분한다.
- 원본 영상과 일반 지식이 충돌하면 충돌 사실을 알리고 원본 확인을 제안한다.
- AI가 생성한 분량 또는 시간을 원본에서 확인된 값처럼 표시하지 않는다.

### 8.4 환각 방지

- 구조화 출력은 서버에서 스키마 검증한다.
- 필수 필드가 없거나 단계 순서가 모순되면 자동 재시도하거나 `NEEDS_REVIEW`로 전환한다.
- 근거가 없는 정확한 숫자 생성을 억제한다.
- 알 수 없는 값은 `null`과 `unknown`으로 보존한다.
- 사용자 질문이 현재 레시피와 무관하면 레시피 근거가 있는 것처럼 답하지 않는다.

### 8.5 안전 응답

다음 주제는 안전 응답 경로를 사용한다.

- 육류, 가금류, 달걀과 해산물의 익힘 상태
- 식품 보관과 상온 방치
- 알레르기와 교차 오염
- 불, 기름, 압력솥과 칼
- 상한 식재료 여부

안전 응답 규칙:

- 사진이나 설명만으로 안전을 확정하지 않는다.
- 가능한 경우 공인된 온도 또는 확인 방법을 안내한다.
- 의심스러운 경우 섭취하지 않도록 보수적으로 안내한다.
- 응급 상황은 앱이 해결할 수 있다고 표현하지 않는다.
- 알레르기 대체재를 제시할 때 제품 라벨 확인을 함께 안내한다.

### 8.6 말투

- 기본 말투는 친근한 존댓말이다.
- 한 번에 한 가지 핵심 행동을 먼저 말한다.
- 과도한 감탄, 칭찬과 이모지를 사용하지 않는다.
- 사용자가 불안해하면 짧게 안심시키되 근거 없는 성공을 장담하지 않는다.
- 스몰토크에서도 조리 진행을 방해할 정도로 길게 답하지 않는다.

### 8.7 AI 평가 세트

출시 전에 최소 다음 범주의 고정 평가 문장을 구축한다.

- 다음 단계 요청 20개
- 현재 단계 완료 표현 20개
- 완료하지 않은 상태에서 다음 정보만 묻는 표현 20개
- 재료 대체 30개
- 이미 사용한 재료 변경 보고 20개
- 농도, 간, 익힘과 식감 문제 40개
- 타임스탬프 요청 10개
- 스몰토크 후 요리 복귀 20개
- 위험 조리 질문 30개
- 모호하거나 상태를 바꾸면 안 되는 표현 30개

평가 항목:

- 의도 분류 정확도
- 잘못된 상태 변경률
- 현재 단계 반영 여부
- 사용자 변경사항 반영 여부
- 근거 없는 숫자 생성률
- 안전 응답 준수율
- 답변 길이와 실행 가능성

| analytics_events | 제품 분석 | 이벤트명, 익명 속성, 발생 시각 |

### 9.2 데이터 소유권과 분리

- 공용 영상 정보와 개인 레시피를 분리한다.
- 사용자 수정, 대화와 조리 기록은 해당 사용자만 접근할 수 있다.
- 모든 개인 테이블에 `auth.uid()` 기반 RLS를 적용한다.
- 클라이언트에 service role 키를 포함하지 않는다.
- AI 제공자에게 보내는 데이터는 기능 수행에 필요한 최소 범위로 제한한다.

### 9.3 데이터 보존

- 분석 실패 로그는 디버깅에 필요한 제한된 기간만 보존한다.
- 음성 원본은 기본적으로 영구 저장하지 않는다.
- 음성을 텍스트로 변환한 뒤 원본을 삭제하는 정책을 기본 가정으로 한다.
- 계정 삭제와 데이터 삭제 정책은 출시 전에 확정하고 앱 안에서 제공한다.

## 10. 분석 이벤트와 핵심 지표

### 10.1 이벤트 명세

| 이벤트 | 발생 조건 | 필수 속성 |
|---|---|---|
| `app_opened` | 앱 활성화 | entry_source |
| `video_link_received` | URL 입력 또는 공유 | input_method, domain |
| `video_validation_failed` | 사전 검증 실패 | reason_code |
| `extraction_started` | 분석 작업 생성 | source_video_id, cache_hit |
| `extraction_completed` | 분석 성공 | duration_ms, review_required, model_version |
| `extraction_failed` | 분석 실패 | reason_code, retryable |
| `recipe_review_started` | 검토 화면 진입 | uncertain_field_count |
| `recipe_field_edited` | 사용자가 항목 수정 | field_type, confidence_before |
| `cooking_started` | 조리 세션 시작 | step_count, voice_enabled |
| `step_completed` | 단계 완료 | step_index, completion_method |
| `step_skipped` | 단계 건너뛰기 | step_index |
| `source_timestamp_opened` | 원본 구간 열기 | step_index, timestamp |
| `chat_question_sent` | 질문 전송 | input_method, intent, step_index |
| `chat_answer_failed` | 답변 실패 | reason_code |
| `session_paused` | 세션 일시정지 | step_index |
| `cooking_completed` | 조리 완료 | duration_seconds, completed_steps |
| `cooking_abandoned` | 조리 중단 | step_index, reason_optional |
| `satisfaction_submitted` | 완료 후 평가 | score, issue_tags |

### 10.2 핵심 지표 정의

#### Activation Rate

```text
요리를 시작한 고유 사용자 수 / 분석에 성공한 고유 사용자 수
```

#### Cooking Completion Rate

```text
완료한 조리 세션 수 / 시작한 조리 세션 수
```

#### Extraction Edit Rate

```text
사용자가 수정한 추출 필드 수 / 사용자에게 표시된 추출 필드 수
```

필드 유형별로 별도 측정한다.

- 재료명
- 분량
- 단위
- 단계 내용
- 단계 순서
- 시간
- 타임스탬프

#### Context Recovery Rate

조리 질문 중 사용자가 현재 단계나 변경사항을 다시 설명하지 않고 유효한 답을 얻은 비율. 자동 산출만으로 확정하지 않고 테스트 세션 표본 검토를 병행한다.

#### Repeat Cooking Rate

```text
첫 완료 후 30일 안에 다른 영상으로 조리를 시작한 사용자 수 / 첫 조리 완료 사용자 수
```

#### AI Cost per Completed Cook

```text
분석 및 대화 AI 총비용 / 완료된 조리 세션 수
```

### 10.3 MVP 성공 판단 기준

정량 목표는 비공개 테스트 표본과 비용을 확인한 뒤 확정한다. 초기에는 다음 방향성을 기준으로 판단한다.

- 사용자의 다수가 분석 결과를 폐기하지 않고 요리를 시작한다.
- 추출 수정이 특정 필드에 집중돼 개선 우선순위를 식별할 수 있다.
- 조리 중 질문의 다수가 현재 단계를 다시 설명하지 않고 해결된다.
- 완료 사용자 중 의미 있는 비율이 다른 영상으로 재사용한다.
- 심각한 잘못된 단계 변경과 안전 위반이 출시 차단 기준 이하로 유지된다.

다운로드 수, 총 대화 수와 생성된 레시피 수만으로 성공을 판단하지 않는다.

## 11. 비기능 요구사항

### 11.1 성능

- 앱 시작 후 홈의 주요 입력 요소는 일반적인 네트워크 환경에서 2초 이내 사용할 수 있어야 한다.
- URL 형식 검사는 즉시 수행한다.
- 분석이 길어져도 앱이 멈춘 것처럼 보이지 않도록 상태를 갱신한다.
- 조리 단계 전환은 로컬 상태를 우선 사용해 체감 지연 없이 동작해야 한다.
- AI 응답은 스트리밍 또는 진행 표시를 제공한다.
- 긴 응답은 핵심 문장부터 먼저 표시하는 방식을 고려한다.

### 11.2 신뢰성

- 분석 요청과 상태 변경 API는 중복 호출에 안전해야 한다.
- 조리 상태는 앱 종료, 프로세스 종료와 네트워크 단절 후 복구 가능해야 한다.
- 로컬 상태와 서버 상태 충돌 시 데이터 유실 없이 사용자가 이어갈 수 있어야 한다.
- 외부 영상 정보 제공 실패가 저장된 레시피와 조리 세션 사용을 막지 않아야 한다.

### 11.3 보안

- Supabase anon 또는 publishable 키만 클라이언트에 포함한다.
- AI API 키와 service role 키는 Edge Functions 비밀값으로 관리한다.
- 사용자 입력은 로그에 원문으로 무제한 저장하지 않는다.
- URL, 텍스트와 AI 구조화 결과를 신뢰하지 않고 서버에서 검증한다.
- RLS 테스트를 자동화한다.
- 인증되지 않은 사용자가 다른 사용자의 레시피, 대화와 조리 세션에 접근할 수 없어야 한다.

### 11.4 개인정보

- 마이크 권한은 음성 입력을 선택한 순간에 요청한다.
- 항상 듣는 기능을 사용하지 않는다.
- 음성 수집 중임을 숨기지 않는다.
- 사용 목적, 보관 여부와 삭제 방법을 개인정보처리방침에 명확히 기재한다.
- 사용자 대화를 모델 개선에 사용할 경우 별도 동의가 필요하다.
- Play Console 데이터 보안 정보는 실제 수집 행위와 일치해야 한다.

### 11.5 접근성

- 본문 및 핵심 조작 요소는 Android 글꼴 크기 확대에 대응한다.
- 색상만으로 불확실성과 상태를 표현하지 않는다.
- TalkBack용 레이블과 올바른 포커스 순서를 제공한다.
- 주요 버튼의 터치 영역은 최소 권장 크기를 충족한다.
- 조리 모드는 고대비 환경과 밝은 주방에서도 읽을 수 있어야 한다.
- 음성 기능을 사용하지 못하는 사용자도 텍스트로 동일한 핵심 흐름을 완료할 수 있어야 한다.

### 11.6 호환성

- 기존 출시 앱과 동일한 `applicationId`를 유지한다.
- 기존 Play App Signing과 업로드 키 체계를 유지한다.
- 기존 출시 버전보다 높은 `versionCode`를 사용한다.
- 지원 Android 버전은 기존 설치 사용자 분포와 주요 라이브러리 요구사항을 확인한 후 확정한다.
- 기존 앱 로컬 데이터와 신규 앱 데이터가 충돌하지 않도록 마이그레이션 또는 명시적 초기화 전략을 마련한다.

## 12. 오류 및 경계 상황

### 12.1 입력 관련

- URL에 불필요한 쿼리 파라미터가 포함됨
- 공유 텍스트에 URL이 여러 개 포함됨
- 재생목록 URL이 입력됨
- 쇼츠 URL이 입력됨
- 라이브 영상 또는 예정 영상이 입력됨
- 삭제, 비공개, 연령 또는 지역 제한 영상
- 요리와 무관한 영상
- 제목은 요리지만 실제 내용은 먹방 또는 리뷰

### 12.2 추출 관련

- 자막 없음
- 자동 자막 품질이 낮음
- 재료는 화면에만 나오고 음성으로 언급되지 않음
- 설명란과 영상의 분량이 다름
- 영상에서 정확한 분량을 말하지 않음
- 여러 요리를 한 영상에서 다룸
- 중간 광고 또는 스폰서 구간이 조리 단계처럼 인식됨
- 자막 언어와 사용자의 앱 언어가 다름
- 영상이 매우 짧거나 매우 김
- 동일 재료를 여러 번 나눠 사용함

### 12.3 조리 관련

- 사용자가 단계를 순서대로 진행하지 않음
- 일부 단계를 이미 수행하고 앱을 시작함
- 재료를 대체한 뒤 다시 원래 재료로 변경함
- 한 단계에서 여러 질문을 함
- 사용자가 “다음”이라고 했지만 현재 단계 완료 여부가 불명확함
- 앱이 종료되거나 기기가 재부팅됨
- 오프라인 상태로 조리함
- 영상이 이후 삭제됨
- 다른 기기에서 같은 세션을 동시에 엶

### 12.4 대화 관련

- 주변 소음으로 음성이 잘못 인식됨
- “됐어”가 완료인지 거절인지 모호함
- 사용자가 영상과 반대되는 행동을 이미 수행함
- 사용자가 위험한 조리 방법을 요청함
- 스몰토크 중 조리 타이밍이 지나감
- AI 응답 중 사용자가 말을 끊음
- 같은 질문에 반복적으로 다른 답이 생성됨

### 12.5 오류 메시지 원칙

- 무엇이 실패했는지 설명한다.
- 사용자의 잘못으로 단정하지 않는다.
- 지금 할 수 있는 다음 행동을 하나 이상 제시한다.
- 내부 오류 코드와 스택 정보를 노출하지 않는다.
- 재시도해도 해결되지 않는 문제에 무한 재시도를 유도하지 않는다.

## 13. 권한과 정책

### 13.1 Android 권한

| 권한 | 필요 여부 | 요청 시점 | 대체 경로 |
|---|---:|---|---|
| 인터넷 | 필요 | 설치 시 선언 | 없음 |

| 카메라 | 불필요 | 요청하지 않음 | 해당 없음 |
| 캘린더 | 불필요 | 요청하지 않음 | 해당 없음 |
| 사진 및 파일 | 불필요 | 요청하지 않음 | 해당 없음 |

### 13.2 유튜브 콘텐츠 처리 원칙

- 지원 방식은 관련 API 및 플랫폼 정책을 준수해야 한다.
- 원본 영상 파일을 무단 저장하거나 재배포하지 않는다.
- 제목, 채널과 원본 링크를 유지한다.
- 타임스탬프 이동은 원본 영상 접근으로 연결한다.
- AI 생성 레시피가 원작자의 공식 레시피와 동일하다고 표현하지 않는다.
- 기술 구현 확정 전 플랫폼 정책과 법률 검토가 필요하다.

## 14. 계정과 온보딩 가정

### 14.1 초기 가정

- 첫 화면에서 회원가입을 강제하지 않는다.
- 익명 세션으로 1회 분석과 조리 체험을 허용하는 방식을 우선 검토한다.
- 저장, 기기 간 동기화 또는 추가 분석 시 계정 연결을 요청한다.
- 구체적인 무료 사용량과 로그인 정책은 AI 비용 실험 후 확정한다.

### 14.2 온보딩 원칙

- 세 장 이상의 기능 소개 슬라이드를 강제하지 않는다.
- 사용자는 1분 안에 링크 입력 화면에 도달할 수 있어야 한다.
- 핵심 사용법은 실제 첫 레시피를 처리하면서 설명한다.
- 마이크 권한과 개인정보 설명을 앱 최초 실행 시 한꺼번에 요구하지 않는다.

## 15. 수용 기준과 QA 체크리스트

### 15.1 출시 필수 사용자 여정

다음 여정은 실제 기기에서 모두 성공해야 한다.

1. 유튜브 앱에서 밥벌이로 링크 공유
2. 영상 확인 후 분석 시작
3. 분석 완료 후 불확실한 항목 확인
4. 재료 하나와 단계 하나 수정
5. 요리 시작
6. 음성으로 현재 단계 반복 요청
7. “여기까지 했어”로 현재 단계 완료
8. 재료 대체 질문 후 변경사항 저장
9. 현재 단계의 원본 영상 구간 열기
10. 앱으로 복귀 후 같은 단계 상태 유지
11. 앱 강제 종료 후 조리 세션 복구
12. 마지막 단계 완료 후 세션 종료

### 15.2 출시 차단 결함

다음 문제가 하나라도 재현되면 출시하지 않는다.

- 다른 사용자의 레시피 또는 대화 접근 가능
- 앱 업데이트 후 서명 또는 패키지 불일치
- 조리 단계가 사용자 확인 없이 임의로 완료됨
- 앱 재실행 후 현재 단계 또는 사용자 변경사항 유실
- AI가 영상에 없는 위험한 조리 정보를 확정적으로 제시
- 음성 녹음 상태를 사용자에게 표시하지 않음
- 마이크 권한 거부 시 앱의 핵심 흐름 사용 불가
- 분석 실패가 유료 또는 무료 사용량으로 잘못 차감됨
- 원본 영상 또는 채널 출처가 제거됨
- 계정 삭제 또는 개인 데이터 삭제 경로가 없음

### 15.3 주요 테스트 범주

- URL 정규화 단위 테스트
- 분석 결과 스키마 검증 테스트
- 중복 분석 멱등성 테스트
- RLS 접근 제어 테스트
- 조리 세션 상태 전이 테스트
- 앱 프로세스 종료 및 복구 테스트
- 네트워크 단절과 재연결 테스트
- 음성 인식 실패 테스트
- 접근성 테스트
- 글꼴 크기 확대 테스트
- 최소 지원 Android 버전 테스트
- AI 고정 평가 세트 회귀 테스트
- 안전 응답 레드팀 테스트

## 16. 출시 단계

### 16.1 1단계 문제 검증

- 타겟 사용자 5~10명의 실제 조리 과정을 관찰한다.
- 영상 되감기, 화면 터치, 별도 검색과 질문 시점을 기록한다.
- 사용자가 실제로 사용하는 짧은 발화를 수집한다.

### 16.2 2단계 기술 검증

- 서로 다른 채널과 영상 형식으로 추출 실험을 수행한다.
- 자막 유무, 쇼츠, 긴 영상과 여러 요리 포함 영상을 구분한다.
- 추출 필드별 정확도와 수정률을 측정한다.
- 타임스탬프 연결 가능 범위를 확인한다.

### 16.3 3단계 내부 알파

- 개발자와 내부 사용자가 전체 사용자 여정을 수행한다.
- 상태 유실, 중복 분석과 AI 상태 오판을 우선 수정한다.
- AI 비용과 응답 지연을 측정한다.

### 16.4 4단계 Play 비공개 테스트

- 기존 출시 앱의 내부 또는 비공개 테스트 트랙을 사용한다.
- 신규 구조가 기존 설치 사용자 기기에서 정상 업데이트되는지 검증한다.
- 실제 주방 환경에서 음성 인식, 가독성과 화면 꺼짐 방지를 확인한다.

### 16.5 5단계 프로덕션 출시

다음 조건을 충족한 후 단계적 출시를 진행한다.

- 출시 차단 결함 0건
- 개인정보처리방침과 Play 데이터 보안 정보 갱신
- 기존 기능 종료와 신규 앱 전환 안내 준비
- 오류 추적 및 비용 모니터링 구성
- 롤백 가능한 이전 안정 버전 보존
- 사용자 문의 및 데이터 삭제 대응 경로 준비

| D-03 | 유튜브 정보 확보 방식 | 허용된 API, 자막 제공 경로, 제한적 수동 입력 | 정책 검토 후 기술 실험으로 확정 |
| D-04 | 음성 출력 기본값 | 항상 켬, 항상 끔, 첫 사용 선택 | 첫 조리 시작 시 선택 |
| D-05 | 타이머 MVP 포함 | 포함, 후속 | 일정이 허용하면 P1로 포함 |
| D-06 | 공용 분석 캐시 | 즉시 도입, 개인 분석만 | 비용을 고려해 공용 원본과 개인 수정 분리 |
| D-07 | 무료 사용량 | 횟수 제한, 기간 제한, 완전 무료 베타 | 비공개 테스트는 무료, 비용 측정 후 결정 |
| D-08 | 기존 사용자 데이터 | 삭제, 보관, 별도 내보내기 | 기존 운영 데이터 현황 확인 후 별도 결정 |
| D-09 | 지원 언어 | 한국어만, 한국어와 영어 | MVP는 한국어 우선 |
| D-10 | Android 최소 버전 | 기존 유지, 상향 | 기존 설치 사용자 분포 확인 후 확정 |

## 19. 출시 후 확장 후보

MVP의 반복 사용이 확인된 뒤 다음 순서로 검토한다.

1. 단계별 타이머와 음성 타이머 제어
2. 인분 및 단위 자동 변환
3. 레시피 수정 전후 비교
4. 실패 복구 답변 품질 강화
5. 사용자 요리 메모와 개인화
6. 틱톡, 인스타그램과 블로그 링크 지원
7. 이미 분석된 레시피 검색
8. 외국어 영상 자동 번역
9. 크리에이터 협업과 공식 레시피 인증
10. 사용자가 동의한 경우 사진 기반 조리 상태 보조

확장 기능은 현재 제품의 핵심인 조리 세션을 방해하지 않는 경우에만 추가한다.

## 20. 최종 MVP 정의

밥벌이 MVP는 유튜브 요리 링크를 구조화된 레시피로 변환하고, 사용자가 결과를 확인·수정한 뒤, 현재 조리 단계와 재료 변경사항을 기억하는 AI와 텍스트 또는 음성으로 대화하며 요리를 완료할 수 있는 Android 앱이다.

MVP가 해결해야 하는 질문은 하나다.

> 사용자는 밥벌이와 함께 요리했을 때 영상을 덜 되감고, 덜 검색하며, 다음 영상에서도 다시 밥벌이를 선택하는가.

이 질문에 답하는 데 직접 기여하지 않는 기능은 MVP 범위에 포함하지 않는다.
