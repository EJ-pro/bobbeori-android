# 밥벌이 MVP 화면 명세

## 0. 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 |
| 작성일 | 2026-10-23 |
| 기준 문서 | `docs/product/PRD.md`, `docs/design/USER_FLOW.md` |
| 대상 | UX/UI, Android, 백엔드, AI, QA |

각 화면은 목적, 진입 조건, UI, 행동, 상태, 오류, 데이터와 이벤트를 동일한 기준으로 정의한다. 문구는 UX 라이팅 과정에서 다듬을 수 있으나 동작 의미는 유지한다.

---

## 1. 공통 UI 규칙

### 1.1 상태 표현

- 로딩 중에는 기존 콘텐츠가 있으면 제거하지 않고 갱신 상태를 덧붙인다.
- 빈 상태는 오류와 구분하고 사용자가 할 수 있는 첫 행동을 제공한다.
- 오류는 원인과 다음 행동을 함께 표시하며 내부 코드나 스택을 노출하지 않는다.
- 성공 토스트만으로 중요한 저장 결과를 전달하지 않는다.
- `inferred`, `unknown`, `사용자 수정`은 색상뿐 아니라 아이콘과 문구로 구분한다.

### 1.2 조작과 접근성

- 핵심 터치 영역은 최소 48dp를 확보한다.
- 주요 버튼은 한 화면에 하나의 우선 행동이 드러나게 배치한다.
- 글자 확대 시 단계 완료·이전·질문 버튼이 접근 불가능해지지 않아야 한다.
- 아이콘 단독 버튼에는 접근성 레이블을 제공한다.
- 녹음, 재생, 저장, 오프라인 상태는 스크린 리더로 전달한다.
- 조리 중 화면은 켜진 상태를 유지하되 세션 종료 시 원복한다.

### 1.3 공통 시스템 요소

- 상단: 뒤로가기, 화면 제목, 필요한 경우 더보기
- 연결 상태: 오프라인 또는 동기화 실패 때만 비차단 배너 표시
- 파괴적 행동: 삭제·세션 중단은 확인 후 실행
- 중복 탭 방지: 서버 작업 생성 버튼은 요청 수락 전 재입력 차단

## 2. S-01 시작 및 초기 안내

**목적:** 제품 가치를 한 문장으로 설명하고 홈으로 빠르게 진입시킨다.  
**진입 조건:** 최초 설치 후 첫 실행 또는 온보딩 미완료.

### 화면 구성

1. 밥벌이 이름과 심볼
2. 핵심 문구: `유튜브 요리를, 따라 하기 쉬운 레시피로`
3. 보조 설명: 링크 분석과 조리 중 대화 도움을 짧게 설명
4. `시작하기` 버튼
5. 개인정보 처리방침 링크

### 동작

- 시작하기 → 온보딩 완료 저장 → S-02
- 시스템 뒤로가기 → 앱 종료 허용
- 마이크·알림·로그인 권한은 요청하지 않는다.

### 상태 및 이벤트

- 별도 네트워크 요청 없이 표시 가능해야 한다.
- `app_opened(entry_source=launcher)` 기록.

### 수용 기준

- 강제 슬라이드가 없고 한 번의 탭으로 홈에 도달한다.
- 재실행 시 다시 노출되지 않는다. 설정에서 도움말로 다시 볼 수 있다.

## 3. S-02 홈

**목적:** 링크 입력·공유 확인과 진행 중 세션 복귀를 제공한다.  
**진입 조건:** 일반 실행, 온보딩 완료, 분석 취소, 완료 또는 중단 후 복귀.

### 정보 우선순위

1. 진행 중 조리 카드(있는 경우)
2. 공유받은 영상 확인 카드(있는 경우)
3. URL 입력 영역
4. 최근 저장 레시피 진입
5. 설정 진입

### 화면 구성

- URL 입력 필드: 붙여넣기, 지우기
- 기본 CTA: `이 영상 분석`
- 지원 예시: 일반 YouTube/Shorts 공유 링크
- 공유 진입 시 썸네일, 제목, 채널, 원본 링크
- 진행 중 세션 카드: 요리명, 현재 단계, 마지막 활동 시각, `이어하기`
- `저장한 레시피` 및 설정 버튼

### 상태

| 상태 | 표현 |
|---|---|
| 기본 | 빈 입력 필드와 사용 예시 |
| 입력 중 | 유효성 검사 전 CTA 비활성 또는 입력 완료 후 검사 |
| 유효 | CTA 활성 |
| 형식 오류 | 필드 하단 오류와 지원 링크 예시 |
| 메타데이터 확인 중 | 영상 카드 스켈레톤, 중복 제출 차단 |
| 공유 링크 확인 | 분석 전에 영상 카드와 확인 CTA 표시 |
| 진행 세션 있음 | 이어하기 카드를 최상단 표시 |
| 오프라인 | 분석은 연결 필요 안내; 저장 세션 이어하기 허용 |

### 동작과 전이

- 분석 선택 → 사전 검증 성공 시 S-03, 실패 시 S-04
- 이어하기 → S-08
- 저장한 레시피 → S-13
- 설정 → S-14
- 새 링크 입력 중 진행 세션이 있으면 기존 세션 종료를 강요하지 않는다.

### 데이터와 이벤트

- 입력: raw shared text 또는 raw URL
- 저장/전달: normalized URL, source video ID, input method
- 이벤트: `video_link_received(input_method, domain)`

### 수용 기준

- URL이 비어 있거나 지원하지 않으면 서버 분석 요청이 발생하지 않는다.
- 공유 텍스트에 문장이 섞여도 첫 지원 URL을 추출한다.
- 빠른 연속 탭으로 분석 작업이 중복 생성되지 않는다.

## 4. S-03 분석 중

**목적:** 분석이 진행 중임을 신뢰할 수 있게 설명하고 이탈·취소 선택을 제공한다.  
**진입 조건:** 서버가 분석 작업 ID를 반환함.

### 화면 구성

- 영상 썸네일, 제목, 채널
- 단계형 진행 표시
- 현재 사용자 문구
- 시간이 길어질 때 `앱을 닫아도 분석은 계속돼요` 안내
- 가능한 구간에서 `분석 취소`
- `홈으로 이동` 보조 행동

### 상태 매핑

| 작업 상태 | 문구 | UI 행동 |
|---|---|---|
| `QUEUED` | 분석을 준비하고 있어요 | 취소 가능 |
| `FETCHING_SOURCE` | 영상 정보를 확인하고 있어요 | 취소 가능 |
| `EXTRACTING` | 재료와 조리 순서를 정리하고 있어요 | 상태 갱신 |
| `VALIDATING` | 빠진 내용이 없는지 확인하고 있어요 | 취소 제한 가능 |
| `COMPLETED` | 결과 준비 완료 | S-05 자동 이동 |
| `NEEDS_REVIEW` | 확인이 필요한 결과 준비 완료 | S-05 자동 이동 |
| `FAILED` | 분석 완료 불가 | S-04 이동 |
| `CANCELLED` | 분석 취소됨 | S-02 이동 |

### 오류/복구

- 상태 조회 실패: 마지막 상태를 유지하고 자동 재시도, 수동 다시 확인 제공
- 앱 재실행: 작업 ID로 상태 복구
- 장기 지연: 백분율을 꾸미지 않고 홈으로 나갈 수 있게 안내

### 이벤트

- 진입 전에 `extraction_started(source_video_id, cache_hit)` 발생
- 성공 시 `extraction_completed(duration_ms, review_required, model_version)`
- 실패 시 `extraction_failed(reason_code, retryable)`

## 5. S-04 분석 실패

**목적:** 실패 이유를 사용자 언어로 설명하고 가능한 복구 경로를 제시한다.  
**진입 조건:** 사전 검증 또는 분석 작업 실패.

### 오류별 구성

| 범주 | 제목 예시 | 주 행동 | 보조 행동 |
|---|---|---|---|
| 잘못된 URL | 유튜브 링크를 확인해 주세요 | 링크 수정 | 입력 지우기 |
| 접근 불가 | 이 영상에는 접근할 수 없어요 | 다른 링크 입력 | 원본 열기 |
| 요리 영상 아님 | 레시피로 정리하기 어려운 영상이에요 | 다른 영상 선택 | 다시 시도 |
| 정보 부족 | 분석할 요리 정보가 부족해요 | 제한 분석(가능 시) | 다른 링크 |
| 외부 서비스 오류 | 잠시 후 다시 시도해 주세요 | 다시 시도 | 홈으로 |
| 형식 오류/시간 초과 | 결과를 완성하지 못했어요 | 다시 시도 | 홈으로 |
| 사용자 취소 | 분석을 취소했어요 | 다시 시작 | 홈으로 |

### 규칙

- 재시도 가능 여부를 오류 코드로 결정한다.
- 같은 작업의 재시도는 멱등 키를 사용한다.
- 시스템 실패는 사용량을 차감하지 않았음을 필요한 경우 명시한다.
- 무한 재시도를 유도하지 않는다.

## 6. S-05 레시피 검토

**목적:** AI 추출 결과를 사용자가 신뢰하고 수정한 뒤 조리 준비로 진행하게 한다.  
**진입 조건:** 분석 상태 `COMPLETED` 또는 `NEEDS_REVIEW`.

### 화면 구성

1. 요리명
2. 원본 영상 카드: 제목, 채널, 썸네일, 원본 열기
3. 인분과 총 예상 시간
4. 불확실 항목 요약 배너
5. 재료 목록
6. 도구 목록
7. 순서가 있는 조리 단계
8. 고정 CTA `요리 준비하기`

### 항목 표시

| 신뢰 상태 | 표시 |
|---|---|
| `confirmed` | 기본 표시 |
| `inferred` | `영상 내용을 바탕으로 추정했어요` |
| `unknown` | `영상에서 확인하지 못했어요` |
| 사용자 수정 | `수정됨` 및 원본으로 되돌리기 |

### 동작

- 항목 선택 → S-06
- 원본 영상 선택 → S-10 또는 외부 영상
- 요리 준비하기 → 유효성 성공 시 S-07
- 뒤로가기 → 저장된 검토 상태 유지 후 S-02

### 차단 조건

- 단계가 0개이거나 모든 단계 내용이 비어 있음
- 요리명이 비어 있음
- 저장 중인 편집 결과를 아직 반영하지 못함

불확실한 분량이나 시간만으로는 시작을 차단하지 않고 명확히 경고한다.

### 이벤트

- 최초 진입: `recipe_review_started(uncertain_field_count)`
- 수정 저장: `recipe_field_edited(field_type, confidence_before)`

---

## 7. S-06 항목 수정

**목적:** 재료와 조리 단계 오류를 사용자가 안전하게 수정한다.  
**진입 조건:** S-05에서 편집 가능한 항목 선택.

### 재료 편집 필드

- 재료명(필수)
- 분량(선택, 숫자 또는 사용자가 입력한 표현)
- 단위(선택)
- 손질 방법(선택)
- 선택 재료 여부
- 삭제

### 단계 편집 필드

- 단계 설명(필수)
- 예상 시간(선택)
- 불 세기(선택)
- 사용 재료 연결
- 주의사항
- 원본 시작/종료 타임스탬프(표시 또는 허용 범위 내 편집)
- 단계 추가·삭제·순서 변경

### 행동

- 저장 → 검증 → 사용자 수정본 저장 → S-05
- 취소/뒤로가기 → 변경이 있으면 버리기 확인
- 원본으로 되돌리기 → 확인 후 해당 항목 복원

### 검증

- 공백만 있는 이름과 단계 설명은 저장 불가
- 음수 분량·시간 불가
- 단계 순서는 저장 후 1부터 다시 정렬
- 마지막 남은 단계를 삭제하려 하면 조리 시작이 불가능해짐을 알림

---

## 8. S-07 요리 준비

**목적:** 조리 전에 재료, 도구와 전체 규모를 빠르게 확인한다.  
**진입 조건:** S-05 필수 검토와 유효성 통과.

### 화면 구성

- 요리명, 인분, 예상 시간, 총 단계 수
- 전체 재료 체크리스트
- 필수 도구 목록
- 불확실하거나 미확인인 항목 안내
- 음성 도움 소개(첫 조리 또는 미설정 시)
- 고정 CTA `요리 시작`

### 동작

- 체크는 준비 편의를 위한 로컬 상태이며 미체크만으로 시작을 차단하지 않는다.
- 미체크 항목이 있으면 시작 시 한 번 알리되 계속 진행 가능하다.
- 요리 시작 → 조리 세션 생성 → S-08
- 뒤로가기 → S-05
- 마이크 권한은 여기서 선요청하지 않고 실제 음성 버튼 선택 시 요청한다.

### 이벤트

- 시작 성공: `cooking_started(step_count, voice_enabled)`

---

## 9. S-08 조리 모드

**목적:** 사용자가 현재 단계에 집중하고 최소 조작으로 진행·질문·원본 확인을 수행한다.  
**진입 조건:** 새 세션 시작 또는 기존 세션 이어하기.

### 화면 정보 순서

1. `현재 단계 / 전체 단계`
2. 지금 해야 할 행동
3. 현재 단계에서 사용할 재료와 분량
4. 불 세기와 예상 시간
5. 주의사항
6. 원본 영상 구간 버튼
7. 이전, 질문/마이크, 단계 완료 버튼

### 보조 표시

- `수정됨` 재료
- 저장/동기화 상태(문제가 있을 때만)
- 음성 낭독 중지
- 미완료 단계 미리보기임을 구분하는 표시

### 행동 규칙

| 행동 | 결과 |
|---|---|
| 단계 완료 | 완료 시각 저장, 다음 단계 이동 |
| 다음 단계 | 미완료이면 완료 또는 건너뛰기 확인 |
| 이전 단계 | 이전으로 이동, 완료 기록 유지 |
| 질문 | S-09 열기, 현재 단계 문맥 유지 |
| 영상 보기 | S-10 외부 열기, 세션 유지 |
| 일시정지/종료 | S-11 열기 |
| 마지막 단계 완료 | 완료 확인 후 S-12 |

### 상태

- 로딩: 로컬 캐시 우선 표시 후 서버와 동기화
- 오프라인: 단계 진행 허용, AI/영상의 네트워크 의존 행동 안내
- 저장 실패: 로컬 저장됨 배너와 재동기화 상태 표시
- 세션 충돌: 현재 기기 상태를 보존하며 충돌 기록; 조리를 차단하지 않음

### Android 동작

- 화면에 진입한 동안 화면 자동 꺼짐 방지 플래그 적용
- 앱 백그라운드/화면 종료 시 세션 즉시 저장
- 외부 영상 복귀 시 동일 세션 및 단계 복원

### 이벤트

- `step_completed(step_index, completion_method)`
- `step_skipped(step_index)`
- `session_paused(step_index)`

## 10. S-09 AI 대화

**목적:** 현재 레시피와 조리 상태를 다시 설명하지 않고 질문하고 도움받는다.  
**진입 조건:** S-08에서 질문 또는 마이크 선택.

### 화면 구성

- 현재 단계 요약 헤더
- 대화 목록
- 텍스트 입력과 전송
- 누르고 말하기 또는 명시적 녹음 시작/종료
- 답변 읽기/중지
- 빠른 질문: `다음은 뭐야?`, `다시 설명해 줘`, `영상으로 보여줘`

### 답변 표현

1. 지금 할 행동
2. 시간·불 세기·판단 기준
3. 위험 또는 실패 방지
4. 필요한 경우 영상 확인

긴 답변도 음성은 핵심부터 읽고 상세는 화면에 남긴다.

### 상태 변경 확인

- `NEXT_STEP_INFO`, `REPEAT_INSTRUCTION`, `TROUBLESHOOT` 등 정보 질문은 상태를 바꾸지 않는다.
- 명확한 `COMPLETE_CURRENT_STEP`은 완료 처리 후 결과를 알린다.
- 재료 변경, 단계 건너뛰기, 세션 종료는 필요 시 확인 칩/다이얼로그를 제공한다.
- AI 답변 생성과 실제 데이터 변경 호출을 분리한다.

### 음성 상태

| 상태 | UI |
|---|---|
| 권한 전 | 사용 목적 설명 후 계속 선택 |
| 녹음 중 | 명확한 색·텍스트·경과 표시와 중지 버튼 |
| 인식 중 | 전송 잠금과 취소 가능 여부 표시 |
| 인식 실패 | 다시 말하기와 텍스트 입력 |
| 권한 거부 | 텍스트 입력 유지, 설정 열기 선택 |

### 실패

- 답변 실패 시 질문 버블을 유지하고 `다시 답변받기` 제공
- 재시도 중 질문을 중복 저장하지 않음
- 불확실한 안전 질문은 단정하지 않고 보수적 행동 안내

### 이벤트

- `chat_question_sent(input_method, intent, step_index)`
- `chat_answer_failed(reason_code)`

## 11. S-10 영상 구간

**목적:** 원작자의 실제 조리 동작을 해당 타임스탬프에서 확인한다.  
**구현 형태:** MVP에서는 YouTube 앱 또는 브라우저로 외부 이동.

### 규칙

- 열기 전에 제목과 채널을 조리 화면에 표시한다.
- 타임스탬프가 있으면 시작 초를 URL에 반영한다.
- 없으면 `이 단계의 정확한 구간을 찾지 못했어요`와 전체 영상 열기를 제공한다.
- YouTube 앱 실패 시 브라우저로 폴백한다.
- 복귀 시 현재 단계와 대화 문맥을 유지한다.

### 이벤트

- `source_timestamp_opened(step_index, timestamp)`

## 12. S-11 일시정지 확인

**목적:** 실수로 조리 세션을 잃지 않게 하면서 이어하기와 종료를 구분한다.  
**진입 조건:** 사용자가 일시정지/나가기/종료를 선택하거나 장시간 후 복귀.

### 유형 A: 잠시 멈춤

- 제목: `요리를 잠시 멈출까요?`
- 행동: `계속 요리`, `일시정지`
- 일시정지 시 현재 단계 저장 후 홈으로 이동

### 유형 B: 요리 중단

- 제목: `이 요리를 그만할까요?`
- 현재 진행 기록이 보존되거나 중단 처리됨을 설명
- 행동: `계속 요리`, 파괴적 행동 `요리 중단`

### 유형 C: 장시간 후 복귀

- 제목: `계속 요리 중인가요?`
- 행동: `이어하기`, `종료`

### 이벤트

- 일시정지: `session_paused(step_index)`
- 중단: `cooking_abandoned(step_index, reason_optional)`

## 13. S-12 요리 완료

**목적:** 완료를 명확히 기록하고 최소한의 품질 피드백을 수집한다.  
**진입 조건:** 마지막 단계 완료 후 사용자가 완료 확인.

### 화면 구성

- 완료 메시지와 요리명
- 완료 단계 수와 조리 시간
- 간단 만족도(예: 1~5 또는 긍정/보통/부정 중 제품 결정 필요)
- 선택 문제 태그: 레시피 정확도, 설명, AI 답변, 영상 구간, 기타
- `완료` CTA, 평가는 건너뛸 수 있음

### 규칙

- 평가 제출 실패가 완료 기록을 되돌리지 않는다.
- 완료 시 화면 자동 꺼짐 방지 상태를 해제한다.
- 완료된 세션에서 뒤로가기로 조리 중 상태를 복원하지 않는다.

### 이벤트

- `cooking_completed(duration_seconds, completed_steps)`
- `satisfaction_submitted(score, issue_tags)`

## 14. S-13 저장한 레시피

**목적:** 이미 분석한 레시피를 다시 열고 분석 비용 없이 재사용한다.  
**진입 조건:** 홈에서 저장한 레시피 선택.

### 화면 구성

- 레시피 카드: 요리명, 썸네일, 채널, 마지막 사용일
- 검색·필터는 MVP에서 제외 가능
- 항목 행동: 열기, 다시 요리, 삭제

### 상태

- 빈 상태: `아직 저장한 레시피가 없어요`와 링크 입력으로 이동
- 로딩 실패: 캐시 표시 후 다시 시도
- 삭제: 확인 후 개인 레시피와 관련 정책에 따른 세션 처리

### 전이

- 열기 → S-05 읽기/검토
- 다시 요리 → S-07
- 삭제 완료 → 목록 갱신

## 15. S-14 설정

**목적:** 음성 경험, 개인정보와 계정 관련 선택을 관리한다.  
**진입 조건:** 홈 또는 관련 안내에서 설정 선택.

### MVP 항목

- 답변 음성 낭독 켜기/끄기
- 음성 인식 결과 전송 전 확인 여부
- 마이크 권한 상태와 Android 앱 설정 열기
- 개인정보 처리방침, 이용약관, 오픈소스 라이선스
- 앱 버전
- 계정 연결/로그아웃/삭제(계정 정책 확정 시)
- 분석 및 개인 데이터 삭제 안내

### 규칙

- 앱 내부 토글은 즉시 저장한다.
- OS 권한 상태와 앱 설정 표시가 불일치하지 않도록 화면 활성화 때 갱신한다.
- 계정 삭제는 대상 데이터와 처리 범위를 설명하고 재확인한다.

## 17. QA 공통 체크리스트

- 각 화면의 로딩·콘텐츠·빈 상태·오류·오프라인 상태를 확인한다.
- 회전, 프로세스 종료, 백그라운드 복귀 후 입력과 현재 단계가 유지된다.
- 빠른 연속 탭으로 분석·세션·메시지가 중복 생성되지 않는다.
- 시스템 뒤로가기와 제스처 뒤로가기가 같은 보존 규칙을 따른다.
- 글자 크기 최대 설정에서 주요 CTA와 조리 행동을 사용할 수 있다.
- TalkBack에서 화면 제목, 현재 단계, 녹음 상태와 버튼 의미를 이해할 수 있다.
- 마이크 권한 거부·영구 거부 후 텍스트 대체 경로가 동작한다.
- 오프라인 단계 이동 후 재연결하면 기록이 유실되지 않는다.
- 외부 YouTube 이동 후 정확한 세션으로 복귀한다.
- 정보 질문이 조리 단계를 임의로 완료하지 않는다.
