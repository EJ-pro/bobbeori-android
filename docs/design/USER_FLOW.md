# 밥벌이 MVP 사용자 흐름

## 0. 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 |
| 작성일 | 2026-10-23 |
| 기준 문서 | `docs/product/PRD.md` v0.1 |
| 대상 플랫폼 | Android |
| 목적 | MVP의 진입점, 화면 전이, 분기 및 복구 흐름 정의 |

이 문서는 사용자가 유튜브 링크를 전달한 순간부터 레시피를 검토하고 요리를 완료할 때까지의 흐름을 정의한다. 화면의 상세 구성은 `SCREEN_SPEC.md`를 따른다.

---

## 1. 설계 원칙

1. 첫 실행에서도 회원가입 없이 링크 입력까지 1분 안에 도달한다.
2. 공유받은 링크는 사용자 확인 없이 자동 분석하지 않는다.
3. AI 분석 결과는 요리 시작 전에 사용자가 검토할 수 있어야 한다.
4. 조리 중에는 현재 단계와 지금 할 행동을 최우선으로 보여준다.
5. 정보 조회와 실제 조리 상태 변경을 구분한다.
6. 실패 시 원인, 데이터 보존 여부, 다음 행동을 함께 제공한다.
7. 앱 종료·네트워크 단절·외부 영상 이동 후에도 조리 상태를 복구한다.
8. 마이크 권한이 없어도 텍스트로 핵심 여정을 완주할 수 있어야 한다.

## 2. 화면 체계

| ID | 화면 | 역할 | 화면 유형 |
|---|---|---|---|
| S-01 | 시작 및 초기 안내 | 첫 사용자에게 핵심 가치 설명 | 전체 화면 |
| S-02 | 홈 | URL 입력, 공유 URL 확인, 진행 중 세션 복귀 | 전체 화면 |
| S-03 | 분석 중 | 분석 진행 상태와 취소 제공 | 전체 화면 |
| S-04 | 분석 실패 | 원인 설명과 복구 행동 제공 | 전체 화면 |
| S-05 | 레시피 검토 | 추출 결과와 불확실 항목 검토 | 전체 화면 |
| S-06 | 항목 수정 | 재료 또는 단계 편집 | 전체 화면/시트 |
| S-07 | 요리 준비 | 재료·도구·예상 흐름 최종 확인 | 전체 화면 |
| S-08 | 조리 모드 | 현재 단계 수행과 단계 전환 | 전체 화면 |
| S-09 | AI 대화 | 현재 단계 기반 질문과 답변 | 바텀시트/전체 화면 |
| S-10 | 영상 구간 | 원본 영상의 해당 시점 확인 | 외부 앱/브라우저 |
| S-11 | 일시정지 확인 | 이어하기 또는 중단 결정 | 다이얼로그/시트 |
| S-12 | 요리 완료 | 완료 기록과 만족도 수집 | 전체 화면 |
| S-13 | 저장한 레시피 | 기존 분석 결과 재사용 | 전체 화면 |
| S-14 | 설정 | 음성·개인정보·계정 설정 | 전체 화면 |

### 2.1 내비게이션 원칙

- MVP에는 하단 탭을 두지 않는다.
- 홈을 루트로 하고 검토와 조리는 단방향 작업 흐름으로 구성한다.
- 시스템 뒤로가기는 편집 중 데이터나 조리 상태가 사라질 때만 확인을 요구한다.
- S-09는 S-08의 현재 단계 문맥을 유지한 채 열리고 닫힌다.
- S-10에서 앱으로 돌아오면 S-08의 동일 단계로 복귀한다.

## 3. 전체 사용자 흐름

```text
앱 실행
├─ 첫 실행 ─ S-01 초기 안내 ─ S-02 홈
├─ 진행 중 조리 있음 ─ 이어하기 ─ S-08 조리 모드
└─ 일반 실행 ─ S-02 홈

S-02 홈
├─ URL 직접 입력
├─ Android 공유로 URL 수신
├─ 저장한 레시피 ─ S-13
└─ 설정 ─ S-14
       ↓
링크 확인 및 사전 검증
├─ 유효 ─ S-03 분석 중
├─ 입력 오류 ─ S-02 인라인 오류
└─ 지원 불가 ─ S-04 분석 실패
                  ↓
분석 작업
├─ 성공 ─ S-05 레시피 검토
├─ 검토 필요 ─ S-05 불확실 항목 강조
├─ 실패 ─ S-04 분석 실패
└─ 취소 ─ S-02 홈
             ↓
S-05 검토 ↔ S-06 항목 수정
             ↓
S-07 요리 준비
├─ 요리 시작 ─ S-08 조리 모드
└─ 뒤로가기 ─ S-05 레시피 검토
                 ↓
S-08 조리 모드
├─ 질문 ─ S-09 AI 대화 ─ S-08
├─ 영상 확인 ─ S-10 외부 영상 ─ S-08
├─ 일시정지/종료 ─ S-11
│  ├─ 이어하기 ─ S-08
│  └─ 중단 ─ S-02
└─ 마지막 단계 완료 ─ 완료 확인 ─ S-12
                                  ↓
                                 S-02
```

## 4. 핵심 흐름 F-01: 직접 링크로 첫 요리 완료

**시작 조건:** 신규 또는 기존 사용자가 앱을 직접 실행한다.  
**성공 조건:** 조리 세션이 `COMPLETED`로 저장된다.

| 순서 | 화면 | 사용자 행동 | 시스템 동작 | 다음 상태 |
|---:|---|---|---|---|
| 1 | S-01 | 시작하기 선택 | 온보딩 완료 상태 저장 | S-02 |
| 2 | S-02 | 유튜브 URL 붙여넣기 | URL 정규화 및 클라이언트 검증 | S-02 |
| 3 | S-02 | 이 영상 분석 선택 | 영상 메타데이터 사전 검증 | S-03 또는 S-04 |
| 4 | S-03 | 대기 | 분석 작업 상태 갱신 | S-05 |
| 5 | S-05 | 결과와 불확실 항목 확인 | 검토 시작 기록 | S-05 |
| 6 | S-05/S-06 | 필요한 항목 수정 | 사용자 수정본 저장 | S-05 |
| 7 | S-05 | 요리 준비 선택 | 필수 값 유효성 확인 | S-07 |
| 8 | S-07 | 재료·도구 확인 후 시작 | 조리 세션 생성 | S-08 |
| 9 | S-08 | 단계 완료/이동/질문 | 현재 단계와 변경사항 자동 저장 | S-08/S-09 |
| 10 | S-08 | 마지막 단계 완료 | 완료 의도 재확인 | S-12 |
| 11 | S-12 | 평가 제출 또는 건너뛰기 | 완료 이벤트와 선택 평가 저장 | S-02 |

### 핵심 분기

- 빈 값 또는 비유튜브 URL: 서버 요청 없이 S-02에서 오류를 표시한다.
- 분석 시간이 길어짐: 작업은 서버에서 계속되며 사용자는 홈으로 나갈 수 있다.
- 불확실한 필드 존재: 요리 시작을 무조건 막지 않되 중요한 분량·단계 누락을 경고한다.
- 단계가 하나도 없음: 요리 시작을 차단하고 S-05에서 수정을 유도한다.

## 5. 핵심 흐름 F-02: Android 공유 메뉴 진입

**시작 조건:** 사용자가 유튜브 앱 또는 브라우저에서 밥벌이로 텍스트를 공유한다.

1. 앱이 종료 상태여도 공유 텍스트를 수신한다.
2. 텍스트에서 첫 번째 지원 가능한 유튜브 URL 후보를 추출한다.
3. S-02에 영상 카드와 URL을 표시한다.
4. 제목·채널·썸네일을 확보할 수 있으면 분석 전에 보여준다.
5. 사용자가 `이 영상 분석`을 눌러야 작업을 생성한다.

### 예외

| 조건 | 처리 |
|---|---|
| URL 없음 | “공유된 내용에서 유튜브 링크를 찾지 못했어요”와 직접 붙여넣기 제공 |
| URL 여러 개 | 첫 후보를 선택하고 다른 링크가 있음을 안내; MVP에서는 한 번에 하나만 처리 |
| 동일 링크 연속 공유 | 기존 진행 작업으로 이동하고 중복 작업을 만들지 않음 |
| 진행 중 조리 있음 | 공유 링크를 보관하고 현재 조리를 계속할지 새 분석으로 갈지 확인 |

## 6. 핵심 흐름 F-03: 분석 작업

```text
QUEUED → FETCHING_SOURCE → EXTRACTING → VALIDATING
                                      ├─ COMPLETED → S-05
                                      ├─ NEEDS_REVIEW → S-05
                                      ├─ FAILED → S-04
                                      └─ CANCELLED → S-02
```

### 사용자 표시 문구 매핑

| 내부 상태 | 사용자 표시 | 취소 |
|---|---|---:|
| `QUEUED` | 분석을 준비하고 있어요 | 가능 |
| `FETCHING_SOURCE` | 영상 정보를 확인하고 있어요 | 가능 |
| `EXTRACTING` | 재료와 조리 순서를 정리하고 있어요 | 정책에 따라 가능 |
| `VALIDATING` | 빠진 내용이 없는지 확인하고 있어요 | 불가 가능 |
| `COMPLETED` | 자동으로 S-05 이동 | 해당 없음 |
| `NEEDS_REVIEW` | 자동으로 S-05 이동, 확인 필요 표시 | 해당 없음 |
| `FAILED` | S-04에서 사용자 언어로 원인 표시 | 해당 없음 |

진행률을 정확히 계산할 근거가 없으면 가짜 백분율을 표시하지 않는다. 단계형 진행 표시와 경과 안내를 사용한다.

---

## 7. 핵심 흐름 F-04: 레시피 검토와 수정

1. S-05 진입 시 요리명, 영상 출처, 인분, 시간, 재료, 도구, 단계를 표시한다.
2. `inferred`와 `unknown` 항목은 아이콘·문구를 함께 사용해 표시한다.
3. 사용자가 항목을 선택하면 S-06으로 이동한다.
4. 저장 시 사용자 수정본만 변경하고 원본 분석본은 보존한다.
5. 수정 취소 시 마지막 저장본을 유지한다.
6. 원본으로 되돌리기는 해당 항목에 한해 확인 후 수행한다.
7. 필수 유효성 검사를 통과하면 S-07로 이동한다.

### 이탈 규칙

- 저장된 변경이 없으면 즉시 이탈한다.
- 저장하지 않은 변경이 있으면 `변경사항을 버릴까요?`를 묻는다.
- 앱이 강제 종료되면 마지막 저장본을 복구한다.

## 8. 핵심 흐름 F-05: 조리 진행

조리 세션 상태는 다음 전이를 따른다.

```text
READY → COOKING → COMPLETED
           ├─ PAUSED → COOKING
           └─ ABANDONED
```

### 단계 이동 규칙

| 사용자 행동/발화 | 처리 |
|---|---|
| 완료 버튼, “여기까지 했어” | 현재 단계 완료 후 다음 단계 이동 |
| “다음 단계로 넘어가” | 미완료이면 완료/건너뛰기 확인 후 이동 |
| “다음은 뭐야?” | 다음 단계 내용을 미리 보여주되 현재 단계는 유지 |
| 이전 버튼, “이전 단계 보여줘” | 이전 단계로 이동, 기존 완료 기록 유지 |
| “이 단계 안 했어” | 확인 후 해당 단계 완료 취소 |
| 마지막 단계 완료 | 요리 완료 확인 표시 |

### 자동 저장 시점

- 세션 시작
- 현재 단계 변경
- 단계 완료·건너뛰기·완료 취소
- 사용자 재료 변경 확정
- 일시정지·재개·중단·완료
- 대화로 확정된 상태 변경

네트워크가 없으면 로컬에 먼저 반영하고 동기화 대기 상태를 표시한다. 서버 저장 실패 때문에 조리 단계 이동을 막지 않는다.

## 9. 핵심 흐름 F-06: AI 대화와 음성

1. 사용자가 S-08에서 질문 버튼 또는 마이크 버튼을 선택한다.
2. 최초 음성 사용 시 목적을 설명한 뒤 Android 권한을 요청한다.
3. 질문 전송 시 레시피, 현재 단계, 완료 단계, 사용자 변경사항과 질문 시점의 단계 ID를 문맥으로 묶는다.
4. 정보 답변은 조리 상태를 변경하지 않는다.
5. 상태 변경 의도는 규칙에 따라 즉시 실행하거나 확인을 거친다.
6. 답변은 지금 할 행동을 먼저 제시하고, 필요하면 음성으로 읽는다.

### 권한 및 실패 분기

| 조건 | 처리 |
|---|---|
| 마이크 허용 | 누르고 말하기 활성화 |
| 마이크 거부 | 텍스트 입력 유지, 설정 이동 선택 제공 |
| 음성 인식 실패 | 인식 실패 문구, 다시 말하기, 텍스트 입력 제공 |
| 답변 생성 실패 | 질문 보존, 다시 시도 제공, 상태 변경 없음 |
| 오프라인 | 현재 단계는 계속 제공, AI 질문은 연결 후 재시도 안내 |
| 안전 판단 불가 | 추측하지 않고 가열 중단 또는 직접 확인 등 보수적 행동 제시 |

## 10. 핵심 흐름 F-07: 원본 영상 확인

1. 사용자가 S-08의 영상 버튼 또는 “영상으로 보여줘”를 선택한다.
2. 타임스탬프가 있으면 해당 시점의 유튜브 링크를 연다.
3. 타임스탬프가 없으면 전체 영상 열기를 제시한다.
4. 유튜브 앱 실행이 실패하면 브라우저로 재시도한다.
5. 앱 복귀 시 동일 조리 세션과 현재 단계로 돌아온다.
6. 외부 영상 재생 여부만으로 단계를 완료하지 않는다.

## 11. 복귀·중단·충돌 흐름

### 앱 재실행

- 진행 중 세션이 있으면 홈 상단에 `요리 이어하기` 카드를 표시한다.
- 즉시 조리 화면으로 강제 이동하지 않는다.
- 사용자가 이어하기를 선택하면 마지막 저장 단계로 이동한다.

### 장시간 백그라운드

- 백그라운드 진입만으로 즉시 `PAUSED` 처리하지 않는다.
- 복귀 시 경과 시간이 길면 `계속 요리 중인가요?`를 표시한다.
- 이어하기는 `COOKING`, 종료는 확인 후 `ABANDONED`로 기록한다.

### 동일 세션 충돌

- 서버 변경과 로컬 미동기화 변경이 모두 있으면 자동으로 최신 시각만 채택하지 않는다.
- MVP에서는 현재 기기의 로컬 진행을 우선 보존하고 서버 사본과 충돌이 있음을 기록한다.
- 데이터가 사라질 가능성이 있는 자동 병합은 하지 않는다.

## 12. 오류 복구 매트릭스

| 실패 지점 | 사용자에게 알릴 내용 | 주 행동 | 보조 행동 | 보존 데이터 |
|---|---|---|---|---|
| URL 형식 오류 | 지원 URL 예시 | 링크 수정 | 입력 지우기 | 입력값 |
| 영상 접근 불가 | 비공개·삭제 등 가능한 이유 | 다른 링크 입력 | 원본 열기 | 없음 |
| 정보 부족 | 분석 정확도가 낮을 수 있음 | 제한 분석 또는 다른 링크 | 취소 | URL/메타데이터 |
| 분석 시간 초과 | 처리가 지연됨 | 다시 확인 | 홈으로 이동 | 작업 ID |
| AI 형식 오류 | 결과를 만들지 못함 | 재시도 | 다른 링크 | 작업/오류 기록 |
| 네트워크 단절 | 연결이 필요함 | 다시 시도 | 로컬 조리 계속 | 세션 상태 |
| 대화 실패 | 질문은 보존됨 | 답변 다시 받기 | 직접 입력 수정 | 질문 원문 |
| 영상 열기 실패 | 재생 앱 또는 네트워크 문제 | 브라우저로 열기 | 조리 계속 | 세션 상태 |
| 저장 실패 | 기기에 임시 저장됨 | 자동 재동기화 | 상태 확인 | 로컬 변경 로그 |

## 14. 흐름 완료 기준

- 직접 입력과 Android 공유 진입이 모두 사용자 확인을 거쳐 분석으로 이어진다.
- 정상·검토 필요·실패·취소 분석 상태에서 막힌 화면이 없다.
- 레시피 수정 후 원본과 사용자 수정본을 구분할 수 있다.
- “다음은 뭐야?”가 현재 단계를 완료하지 않는다.
- 앱 종료, 영상 이동, 네트워크 단절 후 현재 조리 단계를 복구한다.
- 마이크 권한 거부 상태에서도 전체 여정을 텍스트로 완료한다.
- 마지막 단계 완료 전 사용자 확인을 거쳐 세션을 종료한다.
